# AAA 품질 재검토 및 적용 보고서

## 최종 판정

2026-08-07 기준 재검토에서 확인한 필수 개선 항목을 코드, 자산, 테스트와 배포 게이트에 모두 반영했다. 이 프로젝트에서 AAA 품질은 무리한 3D 자산 수량이 아니라 다음 기준으로 관리한다.

현재 판정은 **브라우저 네이티브 상용 품질을 지향하는 검증 가능한 시스템·UX·아트 기반을 갖췄다**는 뜻이다. 대규모 콘솔 AAA 타이틀과 같은 제작 인력·성우·시네마틱·수천 종 아트의 절대 콘텐츠 규모까지 동급이라고 선언하는 뜻은 아니다.

- 플레이 결과가 서로 다른 도메인 상태에 모순 없이 남는다.
- 공간, 주민, 생산, 물류, 원정과 방어의 원인을 화면에서 추적할 수 있다.
- 화면과 소리가 정착지 상태·날씨·시간·피해에 반응한다.
- 저장 손상, 대규모 인구, 모바일 입력과 브라우저 차이를 자동 검증한다.
- 첫 화면부터 엔드게임까지 실제 플레이 명령으로 이어지고 테스트 전용 우회로를 사용하지 않는다.

## 3. 대규모 정착지 성능

- 주민·건물·서비스·노동력 인덱스를 틱마다 한 번 만들고 반복적인 전체 배열 검색을 제거했다.
- 물류 예약과 운송 갱신에서 불필요한 중복 `structuredClone`을 없앴다.
- 인구 220명/350명 구간부터 주민 상태 갱신을 회전형 배치로 전환하고 경과 시간을 보상한다.
- 화면 밖 주민은 집계형 갱신을 사용하며 Phaser 주민 객체 수와 날씨 파티클을 품질 설정별로 제한한다.
- 500명, 180틱 성능 회귀 테스트는 p95 50ms 미만, 전체 5초 미만과 상태 불변식을 강제한다.
- 건물·지형·오버레이 더티 서명, 주민 객체 풀, 경로 LRU 캐시는 유지했다.
- 주민은 화면 안 객체만 보간·프레임 교체하고, 두 보행 아틀라스의 통과 자세를 정지 프레임으로 공유해 별도 정지 텍스처를 런타임에 중복 적재하지 않는다.
- 초기 생존자 8명의 `WORKING` 상태에는 전·후면 작업 PNG 2,238,568바이트(약 2.13MiB, RGBA 약 12MiB)만 적재하고, 훈련·승선·방어 전까지 전·후면 전투 PNG 2,559,509바이트(약 2.44MiB, RGBA 약 12MiB)를 요구하지 않는다. 런타임 적재 중에는 기존 중립 본체와 행동 글리프를 유지하고 완료 뒤 주민 레이어가 새 프레임으로 전환된다.
- 18개 건물 본체 아틀라스를 일괄 선적하지 않는다. 신규 정착지는 핵심 1단계 아틀라스만 먼저 적재하고, 기존 저장은 화면에 존재하는 건물군·단계를, 새 건설과 확장은 선택된 건물군·단계를 Phaser 런타임 로더로 요구 적재한다.
- 이 방식으로 신규 정착지의 초기 경로에서 핵심 2·3단계와 산업·사회·물류/함대·생활/서비스·공공/방어의 기본·2·3단계 PNG 39,838KiB(40,794,572바이트, 약 38.90MiB)와 RGBA 디코딩 메모리 약 102MiB를 유예한다. 단계 이미지 로드 전에는 1단계 본체, 일반 이미지 로드 실패 중에는 절차 실루엣을 유지하고 완료 후 더티 서명으로 장면을 다시 그린다.

## 4. 저장 신뢰성과 복구

- IndexedDB를 v2로 올리고 `saves`와 `backups` 저장소를 분리했다.
- 저장마다 FNV-1a 무결성 값을 기록하고 슬롯별 최근 3개 순환 복구 지점을 보존한다.
- 주 저장의 체크섬이나 스키마 검증이 실패하면 최신 정상 복구 지점을 자동 복원하고 사용자에게 알린다.
- 가져오기 파일은 8MB로 제한한다.
- 음수·비정상 수치, 중복 ID, 최대 객체 수, 지도 크기, 인벤토리, 주민 주거/직장/활동 목적지, 건물 작업자, 운송, 원정, 활성 함선과 타이머의 교차 참조를 검사한다.
- v1/v2/v3 저장을 현재 게임 상태 v4로 마이그레이션한다.
- `sessionStorage`에는 저장 데이터가 아니라 현재 탭의 활성 저장 ID와 선장 생성 초안만 둔다. 동일 탭 재로딩 시 IndexedDB의 검증된 저장을 자동 복원하고, 존재하지 않거나 손상된 슬롯이면 표식을 폐기해 타이틀로 안전하게 돌아간다.
- 새 게임은 활성 표식을 기록한 다음 이벤트 루프에서 첫 IndexedDB 자동 저장을 즉시 시작해 세션 표식과 영구 상태 사이의 간극을 최소화한다. 명시적 타이틀 복귀는 활성 표식을 제거한다.

## 5. UX, 접근성과 모바일

- 모바일 정착지에는 건설·시설·경고·임무·분석의 다섯 개 하단 명령을 제공한다.
- 데스크톱 선택 패널과 모바일 `시설` 명령에 좌표·상태·레벨을 표시하는 시설 장부를 추가해 캔버스에서 찾기 어려운 시설도 즉시 선택하고 카메라를 이동할 수 있다.
- 한 번에 하나의 하단 시트만 열리며 캔버스는 계속 보인다. 배치 성공 후 선택 건물의 공사·재고·병목 시트를 즉시 연다.
- 알림은 심각도에 따라 4.2~7초 후 자동으로 사라지고 `×`로 즉시 닫을 수 있다. 알림 본문은 게임 명령의 포인터 입력을 통과시키며 닫기 버튼만 포인터를 받아 모바일 방어 지휘를 가로막지 않는다.
- Safari의 합성 계층에서 캔버스가 속도 버튼을 가로채지 않도록 HUD 기준 절대 배치를 사용한다.
- 일시정지·설정·저장·승리 모달은 첫 컨트롤에 초점을 주고 `Tab`/`Shift+Tab`을 내부에서 직접 순환시킨다.
- 현재 내비게이션에는 `aria-current`를 부여하고 장식 아이콘을 접근성 트리에서 제외했다.
- 고대비, UI 크기, 색각 보정, 동작 감소 설정을 유지한다.
- 관리 화면은 동적 import로 분할했다. 초기 페이지 노드는 약 51KB 원시 크기이며 Phaser는 약 1.20MB 원시/319KB gzip의 지연 로드 엔진 청크로 격리된다.

## 6. 사운드, 설치와 오프라인

- 외부 Google Fonts 요청을 제거하고 설치 글꼴과 시스템 대체 글꼴을 사용하는 로컬 우선 타이포그래피를 구성했다.
- 프로젝트 전용 Ogg/Vorbis 바다, 항구, 비 루프와 대포, 선체 충돌 효과음을 포함한다.
- Web Audio 다이내믹 컴프레서, 컨볼루션 잔향, 공간 팬, 재생률 변형, 날씨와 도시 활동 기반 믹싱을 구현했다.
- Ogg 디코딩이나 자산 요청 실패 시 절차 합성 오디오로 폴백한다.
- 서비스 워커는 버전별 앱 셸, 최대 80개 런타임 항목, 내비게이션 전용 오프라인 폴백, 범위 요청 제외와 이전 캐시 정리를 수행한다.
- 192px/512px PNG와 SVG 설치 아이콘, 독립 실행형 매니페스트를 제공한다.

E2E는 새 선장 생성, 15종 지형·58종 건물 본체·6종 건물 성장·8개 주민 역할의 전·후면 보행 및 작업·전투 3프레임 아틀라스 실제 PNG와 24프레임 JSON 응답, 초기 작업 본체 적재와 전투 본체 유예, 신규 정착지에서 불필요한 17개 건물·단계 아틀라스를 요청하지 않는지, 난파선 잔해를 제외한 57종 건물의 2·3단계 PNG가 배포되지만 초기에는 적재되지 않는지, 건설 선택 시 필요한 건물군만 요청하는지, 시설 장부에서 화톳불을 선택해 자재 운반과 공사를 거쳐 1→2→3단계로 확장할 때 각 전용 본체 PNG가 순서대로 요청되는지 검증한다. 그 밖에 실제 캔버스 배치와 자재 운반, 관리 화면, 임무 수락, 9개 등급 함선 아틀라스를 사용하는 실시간 기함 출격, 방어 작전, 저장/복원, 선장 생성 초안과 활성 항해의 동일 탭 재로딩 복구, 물류 오버레이, 고정 헤더·푸터, 비차단 알림 본문, 자동·수동 알림 닫기와 키보드 포커스를 사용자 입력으로 실행한다. 저장소 조회는 저장 결과 검증에만 사용하며 게임 상태를 조작하지 않는다. 캐시 재검증의 정상 304 응답도 허용하되 그 외 비정상 상태는 URL과 상태 코드를 포함해 실패한다. WebGL과 대형 아틀라스의 프로젝트 간 자원 경쟁을 피하도록 행렬은 직렬 실행하고, 앱 자체 캐시 교체가 기능 테스트를 재초기화하지 않도록 E2E 컨텍스트의 서비스워커만 차단한다. 서비스워커 산출물 자체는 프로덕션 빌드 게이트에서 생성 여부를 검증한다.

## 8. 원본 지형 자산과 재현성

- 프로젝트 전용 15종 지형 표면은 내장 이미지 생성 도구의 `stylized-concept`로 초안을 만들고 `precise-object-edit`로 누락·크롭 없이 정렬했다. 외부 폴백 도구는 사용하지 않았다.
- 6종 건물 성장·상태 장식은 기존 건물 아틀라스를 스타일 참조로만 사용해 내장 이미지 생성 도구의 `stylized-concept`로 제작했다. 완성 건물을 복제하지 않고, 50종 이상 건물에 결합할 수 있는 열린 외곽 소품으로 제한했다.
- 산업 9종, 주거·복지·군수·행정 9종, 물류·수직 기반시설·함대 12종, 생산·생활·공공·방어 16종과 주민 8개 역할의 후면 및 전·후면 3프레임 보행·작업·전투는 기존 아틀라스를 스타일·정체성 참조로 사용해 내장 이미지 생성 도구로 제작했다. 작업·전투 아틀라스는 긴 도구가 이웃 역할에 침범하지 않도록 역할별 무기 각도와 프레이밍을 정밀 편집한 뒤, 실제 알파 0 분리선을 기준으로 24프레임 JSON을 작성했다. 난파선 잔해를 제외한 핵심·산업·사회·물류 및 함대·생산 및 생활 서비스·공공 및 방어 57종의 2·3단계는 기존 기본 아틀라스와 직전 단계를 각각 편집 대상으로 삼아 셀 위치·건물 정체성을 유지한 전용 완성 본체로 제작했다. 사회 건물 초안의 인물 세 명은 `precise-object-edit`로 제거하고 가려진 건물 부분만 복원했으며, 3단계 연기 잔상은 건물을 보존한 정밀 편집으로 제거했다. 신호탑과 현상금 계약소는 프레임 경계를 넘지 않도록 전체 구조의 위치만 정밀 보정했다.
- 단색 크로마 배경을 로컬에서 알파로 변환하고 JSON 프레임을 명시해 런타임 자동 분할이나 위치 추정에 의존하지 않는다.
- `terrainArt.test.ts`가 모든 `TerrainType`의 누락 없는 고유 프레임 매핑과 혼합 범위를 검사하고, Playwright가 브라우저에서 PNG 요청 성공을 확인한다.
- 최종 자산 경로와 정확한 프롬프트 세트는 [`art-generation-provenance.md`](art-generation-provenance.md)에 보존했다.

## 결론과 제작 범위

재검토에서 발견된 코드·시스템·UX·신뢰성·성능 항목과 지형·건물 성장·주민 활동의 주요 시각 격차는 적용·검증됐다. 전용 건물 본체는 12종에서 58종으로 늘어 현재 카탈로그의 모든 건물 타입이 공통 실루엣 폴백 없이 고유 본체를 가지며, 난파선 잔해를 제외한 57종 전체가 2·3단계 완전 변형까지 갖췄다. 주민은 8개 역할의 전·후면 보행과 생산·소방·훈련·승선·방어용 전용 3프레임 루프를 갖췄다. 현재 빌드는 완결된 핵심 루프와 상용 수준의 기술 기반을 갖추지만, “대규모 AAA 제품과 제작 규모까지 동급”이라는 확정은 여전히 하지 않는다. 다음 제작 격차는 식사·의료·오락의 전용 다프레임 행동, 주민의 성별·연령·체형 변주, 전문 성우·오케스트라 녹음, 시네마틱 사건, 장기 캠페인용 추가 서사와 반복 플레이 변주다.
