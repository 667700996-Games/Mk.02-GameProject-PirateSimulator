# 공간 기반 해적 정착지 시뮬레이션 전환 설계

## 목표와 전환 원칙

`Mk.03-PirateSimulator`의 기존 결과물을 폐기하지 않고, 표현 계층과 검증된 해적 도메인을 재사용한다. 게임의 중심은 실시간 함선 직접 조종에서 해적 공동체의 공간·생산·물류·인구·함대 운영으로 이동한다. 기존 항해와 승선 콘텐츠는 원정 중 발생하는 전술 콘텐츠로 유지하고, 정착지 시뮬레이션이 모든 자원과 인력의 출발점이 되게 한다.

Phaser 3를 단일 게임 렌더러로 유지한다. Svelte는 정보 계층과 관리 명령을 담당하고, Phaser는 실제 섬·건물·주민·화물·환경 표현과 공간 입력을 담당한다. 새 렌더링 라이브러리는 추가하지 않는다.

## 재사용 가능한 코드와 자산

- `src/lib/components/TitleScreen.svelte`, `CaptainCreation.svelte`: 시각 품질과 신규 게임 진입 흐름을 보존한다.
- `src/lib/components/GameShell.svelte`, `GameHeader.svelte`, `GameNav.svelte`: 도시 모드 전역 셸과 화면 상태 라우팅의 기반이다.
- `src/app.css`: Dark Pirate Maritime Command 색상, 타이포그래피, 황동·목재·해양 패널 토큰을 도시 HUD에 확장한다.
- `src/lib/game/SeaGame.ts`, `SeaScene.ts`: Phaser 초기화, Svelte 브리지, 전술 해상 표현을 재사용한다. 정착지에는 같은 구조의 독립 Scene을 둔다.
- `src/lib/audio/SoundEngine.ts`: 도시·항만·경보 분위기와 작업 효과음을 추가하는 기반이다.
- `src/lib/domain/catalog.ts`: 선장 특성, 선급, 해역, 세력, 기존 시설 정의를 새 데이터 카탈로그와 연결한다.
- `src/lib/domain/combat.ts`, `boarding.ts`, `raid.ts`, `defense.ts`: 원정 및 본거지 방어의 결과 계산기로 유지한다.
- `src/lib/domain/fleet.ts`, `voyage.ts`, `missions.ts`: 전략 원정 상태 머신과 계약 시스템으로 점진적으로 확장한다.
- `src/lib/persistence/gameRepository.ts`, `migrations.ts`: 저장 슬롯과 버전 마이그레이션의 기반이다.
- `static/art/pirate-haven-keyart.png`: 타이틀 품질을 유지하고 도시 진입·원정 결과의 환경 아트로 재사용한다.

## 제거 또는 교체할 코드

삭제보다 호환 계층을 우선한다. v2 저장을 불러온 뒤 새 정착지 상태를 생성할 수 있도록 기존 구조는 당분간 유지한다.

- `HavenScreen.svelte`의 시설 카드 클릭 건설은 실제 지도 배치 명령으로 교체한다. 카드는 건설 도감과 선택 건물 정보로 재사용한다.
- `haven.ts`의 `tickHavenDay`가 임의로 목재·식량·화약·금화를 생성하는 흐름은 중단한다. 새 생산·물류 결과를 기존 `HavenState` 요약값과 `ResourceStock`에 동기화한다.
- `buildFacility`의 시간 기반 집계 시설은 공간 건물의 호환 어댑터로만 남긴다.
- `fleet.ts`의 시간 만료 후 즉시 보상하는 명령은 보급 적재, 경로, 단계, 사건, 귀환 화물을 가지는 원정 상태 머신으로 교체한다.
- 함선 상점 즉시 구매는 비활성화하고 조선소 건조 대기열의 완료 결과로만 함선을 생성한다.
- 기존 본거지 배경의 CSS 건물 실루엣은 실제 도시 화면에서 사용하지 않는다. 타이틀과 로딩 연출에는 유지한다.

## 신규 도메인 모델

### 정착지 공간

- `SettlementSimulationState`: 버전, 시뮬레이션 시각, 속도, 섬, 건물, 주민, 물류, 재고, 건조, 원정, 위협, 발전, 정책, 통계, 경고를 소유한다.
- `IslandMapState`: 가로·세로, 시드, 타일 배열, 탐사 상태를 가진다.
- `IslandTile`: 격자 좌표, 지형, 높이, 자원 매장, 물/건설 가능/이동 비용을 가진다.
- `SettlementBuilding`: 정의 ID, 좌표, 회전, 점유 크기, 레벨, 상태 머신, 건설 진행도, 작업자, 내부 입출력 재고, 우선순위, 손상·화재를 가진다.
- 건물 상태는 `PLANNED → CONSTRUCTING → ACTIVE`, 그리고 `PAUSED`, `BLOCKED`, `DAMAGED`, `BURNING`, `DESTROYED`, `UPGRADING` 전이를 명시적으로 관리한다.

### 자원·생산·물류

- `SettlementResourceDefinition`: 40종 이상의 기초·가공·생활·군수·고급·전리품 자원을 데이터로 정의한다.
- `RecipeDefinition`: 입력, 출력, 생산 시간, 필요 직업·인원, 연료·도구, 위험을 정의한다.
- `Inventory`: 시설별 실제 재고를 가진다. 중앙 전역 수치는 모든 저장 위치의 읽기 전용 집계다.
- `TransportJob`: 출발 시설, 목적 시설, 자원, 수량, 예약량, 담당 운반자, 경로, 진행 상태와 우선순위를 가진다.
- 자원은 생산시설 출력 → 운반 예약 → 운반자 이동 → 목적지 입고 순서로만 이동한다.

### 주민·노동

- `Resident`: 이름, 계층, 직업, 숙소, 근무지, 건강, 사기, 충성도, 피로, 욕구, 장비, 위치, 경로, 현재 행동을 가진다.
- 계층은 표류자, 잡역부, 숙련 노동자, 전문 해적, 정예 해적, 장교·선장으로 구성한다.
- `WorkforcePolicy`: 산업별 우선순위, 최소·최대 인원, 자동 재배치, 숙련자 우선 여부를 가진다.
- 화면 안 주민은 경로와 애니메이션을 갱신하고, 화면 밖 주민은 일정 간격의 배치 계산으로 생산·소비만 갱신한다.

### 함선·원정·방어

- `ShipConstructionOrder`: 선급, 예약 자원, 필요 조선공, 진행 시간, 상태를 가진다.
- `StrategicFleet`: 기함, 역할별 함선, 장교·선원, 식량·물·탄약·의약품·화물, 사기, 속도, 정찰력, 전투력을 가진다.
- `Expedition`: `PREPARING → DEPARTING → TRAVELING → EVENT/COMBAT → RETURNING → COMPLETED/LOST` 상태를 명시한다.
- `InvasionThreat`: 공격 함대, 발견 시각, 도착 예상, 목표, 준비 상태를 가진다. 해안 포대는 작업자와 현장 탄약 재고가 모두 있어야 발사한다.

### 발전과 통치

- 발전 축은 `악명`, `번영`, `항해술`, `해적 연방` 네 가지이며 각 항목은 비용, 선행 조건, 실제 해금 효과를 가진다.
- 정책은 전리품·노동·식량·포로·외교 범주별로 하나씩 활성화하며 생산성, 사기, 충성도, 위협, 가격에 장단점을 적용한다.

## 단계별 구현 계획

1. 저장 v4와 데이터 카탈로그: 자원 40종 이상, 건물, 생산법, 계층, 욕구, 직업, 함선 건조, 발전, 정책을 정의하고 v1·v2·v3 저장을 순차 이주시킨다.
2. 도시 건설 기반: 결정적 섬 지도, 아이소메트릭 카메라, 지형·높이 렌더링, 건물 미리보기·회전·배치·선택·이동·철거·업그레이드·일시정지를 완성한다.
3. 생산과 물류: 건설 자원 예약, 채취, 다단계 생산, 건물별 재고, 실제 운반 작업, 창고와 병목 오버레이를 연결한다.
4. 주민 시뮬레이션: 개별 주민, 숙소, 직업 배치, 이동, 욕구, 사기, 계층 상승과 LOD를 구현한다.
5. 도시 정보 UI: 상단 지표, 건설 메뉴, 선택 정보, 경고, 게임 속도, 물류·식량·인력·위험 오버레이와 원인 추적을 제공한다.
6. 함선과 원정: 자원·조선공이 필요한 건조, 함대 구성·보급·경로·위험 예측, 단계형 원정과 귀환 화물을 연결한다.
7. 약탈·전투·방어: 기존 전투 계산과 표현을 원정에 연결하고, 해안 포대 현장 탄약과 작업자·함대 귀환이 침공 결과에 반영되게 한다.
8. 발전·정책·경제: 네 발전 축, 통치 정책, 공급·사건 기반 가격을 연결한다.
9. 완성도와 검증: 튜토리얼, 낮밤·날씨·환경 활동, 사운드, 성능 계측, 단위·통합·E2E 테스트와 문서를 완성한다.

각 단계는 독립 데모가 아니라 이전 단계와 연결된 플레이 가능한 수직 흐름으로 끝낸다.

## 성능 전략

- 섬과 건물은 정적 레이어·변경 레이어로 나누고, 변경된 타일과 개체만 다시 그린다.
- 아이소메트릭 좌표와 점유 셀, 인접성, 경로를 캐시한다.
- 주민은 `VISIBLE`, `NEAR`, `AGGREGATED` 세 단계 LOD로 갱신한다. 500명 구조에서도 화면 밖 주민은 매 프레임 이동하지 않는다.
- 생산·욕구·경제 계산은 고정 시뮬레이션 틱으로 배치하고 렌더 프레임과 분리한다.
- 건물·주민·화물 아이콘·연기·불꽃은 객체 풀을 사용하며 파티클 상한을 품질 설정에 연결한다.
- Svelte에는 집계 HUD와 선택 개체만 전달하고 전체 주민 배열을 컴포넌트별로 순회하지 않는다.
- 저장에는 텍스처·경로 캐시·집계 통계를 넣지 않고 원본 상태만 저장한다. 불러올 때 파생 데이터를 재구성한다.
- 시뮬레이션 계측값으로 프레임 시간, 활성 주민, 대기 운송, 막힌 생산, 경로 캐시 적중률을 확인할 수 있게 한다.

## 완료 기준의 기술적 해석

“실제” 건설과 물류는 시각적 연출만을 뜻하지 않는다. 건물 점유 셀·지형 규칙·입출력 재고·예약된 운송·담당 주민·도착 시 입고가 저장 상태에 존재하고, 생산·함선 건조·방어가 그 상태를 소비해야 한다. 어떤 핵심 버튼도 결과 없는 장식 명령으로 두지 않는다.
